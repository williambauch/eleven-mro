⚠️ Pontos a reavaliar:
  1. O auto-approve do motor O&A (mro_engine.php) manda PENDING_OA → RELEASED direto, sem criar assignments — mesmo problema do Bug 1. Aguarda decisão do superior (ver MRO-122, seção "Bug 1 — EXTENSÃO").
  2. O auto-approve "Dentro do CAP?" = Sim (btn_validar_prog → fn_calcular_oa_nrc) também vai direto para RELEASED sem criar assignments. Como o btn_liberar_para_execucao do grid só age sobre APPROVED, a NRC fica em RELEASED sem equipe alocada e ninguém consegue criar assignments depois.
  3. SUPSIG → CLOSED não implementado: o status CLOSED não existe na tabela mro_sys_status. O control_pause_task (motivo 6, conclusão) manda o assignment para SUPSIG, mas não há código que faça a transição SUPSIG → CLOSED. Assignments concluídos ficam em SUPSIG indefinidamente. O COMPLETED (em cinza 50% no diagrama) só existe vindo do P6 na importação — nenhum código do fluxo de execução gera COMPLETED.
